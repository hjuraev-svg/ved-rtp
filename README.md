# ВЭД RTP — Real-Time Pipeline

Gmail va Telegram ulanishi bo‘yicha amaliy qo‘llanma: [INTEGRATIONS.md](INTEGRATIONS.md).

## Ishchi muhit

Asosiy ishchi tizim — `https://jnslabsonline.uz/ved`. Laptopdagi ushbu papka
faqat kodni GitHub bilan xavfsiz saqlash uchun ishlatiladi; u avtomatik ravishda
lokal Docker serverini ishga tushirmaydi. Kod o‘zgarishlari Windows ish paytida
har besh daqiqada GitHub’ga yuboriladi.

Оперативная система контроля внешнеэкономической деятельности. Это рабочая
замена файлу `Дашборд_ВЭД.xlsx`: те же **18 блоков**, тот же **чек-лист из 24
пунктов**, те же нормативы «красной зоны» — но с живыми данными, историей
движения, контролем документов и обновлением у всех пользователей одновременно.

```
Excel                          →   ВЭД RTP
─────────────────────────────────────────────────────────────
Лист «Дашборд ВЭД» (18 плиток) →   Дашборд с живыми счётчиками
Лист «Описание блоков»         →   Справочник блоков + нормативы SLA
Лист «Чеклист ВЭД» (24 пункта) →   Чек-лист на каждую сделку
Ручной подсчёт                 →   Автоматические KPI и алерты
Один файл у одного человека    →   Многопользовательский доступ по ролям
```

## Быстрый старт

Требуется только **Docker Desktop**.

```bash
docker compose up -d --build
```

Откройте **http://localhost:8090**

Вход: **`Samandar`** / **`<см. .env на сервере>`** (меняется в `.env` — `ADMIN_EMAIL` / `ADMIN_PASSWORD`).

> **Рабочий сервер: https://jnslabsonline.uz/ved/** — развёрнут и обновляется
> скриптом `./deploy.sh`. Подробности в [DEPLOY.md](DEPLOY.md).

> Порт **8090**, а не 8080: на этой машине 8080 уже занят контейнером
> `aromaweb-aroma-web-1`. Меняется через `WEB_PORT` в `.env`.

Остальные адреса:

| Адрес | Что это |
|---|---|
| http://localhost:8090 | Веб-интерфейс |
| http://localhost:8000/docs | Swagger — вся API документация |
| http://localhost:8000/api/health | Проверка состояния |
| `localhost:5433` | Postgres (логин/пароль из `.env`) |

### Пользователи

Сейчас в `.env` установлено `SEED_DEMO=false` — база чистая, есть только
администратор `Samandar`.

Логин — это имя пользователя **или** email; регистр не важен
(`Samandar` = `samandar` = `SAMANDAR`). Пароль — от 4 символов.

Смена логина/пароля администратора: поправить `ADMIN_EMAIL` / `ADMIN_PASSWORD`
в `.env` и пересоздать базу (`docker compose down -v && docker compose up -d`) —
учётная запись создаётся только на пустой базе.

Остальные учётные записи заводит администратор на странице
**«Пользователи»** (пункт меню виден только роли `admin`): создание, смена
логина, имени, роли и пароля, перевод в архив.

Пользователей нельзя удалить — на них ссылаются сделки, отметки чек-листа и
история движения. Вместо удаления — архив: вход блокируется, прошлые записи
сохраняются.

Защита от потери доступа: нельзя снять права администратора с самого себя,
отключить свою учётную запись или убрать последнего активного администратора.

Доступные роли: `admin`, `director`, `ved`, `logist`, `warehouse`,
`accountant`, `broker`, `viewer`.

Если поставить `SEED_DEMO=true` и пересоздать базу (`docker compose down -v`),
дополнительно появятся демо-учётные записи с паролем `demo123`:
`ved@`, `director@`, `logist@`, `sklad@`, `buh@`, `viewer@ved.local` — вместе с
24 демонстрационными сделками.

Остановить: `docker compose down` · Удалить вместе с данными: `docker compose down -v`

## Что внутри

### Три типа сделки

У каждого типа свой маршрут этапов, свой комплект документов и своя нумерация.
Тип выбирается при создании сделки и переключается вкладками на дашборде,
в аналитике и в справочнике блоков.

| Тип | Код | Этапы |
|---|---|---|
| **Импорт (ВЭД)** | `ВЭД-2026-001` | 18 блоков исходного дашборда (без изменений) |
| **Местный поставщик** | `МП-2026-001` | Выбор поставщика → Подписание контракта → Оплата / начало производства → Отгрузочные документы → Прибытие на склад |
| **Услуга** | `УСЛ-2026-001` | Забор от производителя → Авто / авиа отправка → Ставка → Статус и срок → Стоимость услуги → Прибытие на склад → Завершено |

Этапы не смешиваются: сделку нельзя перевести на этап чужого типа, а комплект
документов создаётся свой (в местной закупке нет ГТД, в услуге — контракта).

Чек-лист из 24 пунктов существует только у «Импорта» — это лист исходного
Excel. У двух других типов вкладка «Чек-лист» пустая: контроль идёт по маршруту
этапов. Пункты можно задать, когда они появятся.

### Дашборд

18 плиток в пяти группах — ровно как на листе «Дашборд ВЭД»:

| Группа | Блоки |
|---|---|
| **Закупка** | 1. Заявки от производства · 2. RFQ в работе · 3. Полученные КП · 4. Выбор поставщика |
| **Контракт и финансы** | 5. Контракты на согласовании · 6. Подписанные контракты · 7. Валютный контроль (УНК) · 8. Подтверждение поступления денег |
| **Производство и отгрузка** | 9. Заказы в производстве · 10. Упаковка / маркировка · 11. Фрахт / транспорт · 12. Отгрузки в пути (ETD/ETA) |
| **Документы и таможня** | 13. Отгрузочные документы · 14. Документы у брокера · 15. Растаможка (ГТД) · 16. Прибытие на склад |
| **Приёмка** | 17. Входной контроль · 18. Акт / претензии |

Клик по плитке открывает список сделок этого этапа, уже отфильтрованный.

**Своя раскладка у каждого пользователя.** Кнопка «⠿ Настроить» включает режим
редактирования: плитки перетаскиваются мышью на новое место, «глаз» скрывает
ненужные. «Готово» сохраняет, «Сбросить» возвращает порядок по процессу
(1 → 18). Раскладка привязана к учётной записи — у каждого своя, чужую она не
меняет.

Цвет плитки = группа процесса (легенда над плитками). Красная цифра в углу —
сколько сделок этого блока в красной зоне.

Перетаскивание работает мышью на компьютере; на планшете порядок меняется
только через сброс — сенсорный drag-and-drop не поддерживается.

### Красная зона — считается автоматически

Нормативы взяты из колонки «Как считается» листа «Описание блоков»:

| Блок | Правило красной зоны |
|---|---|
| 1. Заявки | без движения > 5 дней |
| 5. Контракты на согласовании | > 10 дней |
| 9. Заказы в производстве | отклонение факта от плана готовности > 5 дней |
| 12. Отгрузки в пути | ETA прошла без отметки о прибытии, либо ETA сдвинута |
| 15. Растаможка (ГТД) | > 3 **рабочих** дней от подачи до выпуска |
| 7. Валютный контроль | контракт подписан, но УНК не зарегистрирован |
| остальные | норматив по умолчанию, редактируется в «Справочнике блоков» |

Нормативы меняются в интерфейсе (роли `admin` / `director`), перезапуск не нужен.

### KPI

Активные сделки · Красная зона · Контракты за месяц и сумма по валютам · В пути ·
Прибывает за неделю · Средний срок растаможки (рабочих дней) · Готовность
документов (получено / требуется × 100 — формула из блока 13) · УНК
зарегистрировано / не хватает · Открытые претензии и их сумма.

### Карточка сделки

* **Степпер** по 18 этапам — перевод в один клик, с комментарием и записью в историю
* **Чек-лист** — 24 пункта, пункты текущего этапа подсвечены
* **Документы** — комплект из 9 типов, отметка получения, номер, загрузка файла
* **КП** — таблица сравнения по цене / сроку / условиям, минимальная цена выделена;
  выбор поставщика с указанием причины (цена / срок / качество / рекомендация)
* **Претензии** — сумма, статус урегулирования
* **История** — все переходы с временем, проведённым на каждом этапе
* **Комментарии**

### Реальное время

WebSocket-канал: любое изменение (перевод этапа, отметка документа, новое КП)
мгновенно обновляет дашборд у всех, кто его открыл. Индикатор «Онлайн» в шапке.
При обрыве связи клиент переподключается с нарастающей паузой.

### Роли

| Роль | Права |
|---|---|
| `admin` | всё, включая пользователей и нормативы |
| `director` | редактирование данных + нормативы блоков |
| `ved`, `logist`, `warehouse`, `accountant`, `broker` | редактирование данных |
| `viewer` | только просмотр |

Управление — страница «Пользователи» (только для `admin`).

## Настройка

Все параметры — в `.env` (создаётся копированием `.env.example`).

```ini
WEB_PORT=8090            # порт веб-интерфейса
API_PORT=8000            # порт API
POSTGRES_PORT=5433       # порт Postgres на хосте
JWT_SECRET=...           # обязательно смените для реальной эксплуатации
ADMIN_EMAIL=Samandar     # логин: имя пользователя или email
ADMIN_PASSWORD=<см. .env на сервере>      # создаётся только на пустой базе
SEED_DEMO=false          # true — 24 демо-сделки и демо-пользователи
TZ=Asia/Tashkent
```

### Демо-данные

Управляется флагом `SEED_DEMO` в `.env`. Сейчас **выключен**.

Чтобы переключить, поменяйте флаг и пересоздайте базу:

```bash
docker compose down -v
docker compose up -d
```

`down -v` обязателен: демо-данные создаются только когда таблица сделок пуста,
поэтому без сброса тома флаг ни на что не повлияет.

Справочники (18 блоков, 24 пункта чек-листа, 9 типов документов) создаются
всегда, независимо от флага.

### Порт занят

Поменяйте `WEB_PORT` в `.env` и выполните `docker compose up -d`. Занятые
на этой машине порты: 8080, 8088, 8001, 8002, 5000, 5432.

## Управление

```bash
docker compose logs -f api        # логи бэкенда
docker compose ps                 # состояние контейнеров
docker compose restart api        # перезапуск API
docker compose down               # остановить (данные сохраняются)
docker compose down -v            # остановить и стереть базу
```

### Проверка работоспособности

```bash
python backend/smoke_test.py
```

Проверяет авторизацию, справочники (18 блоков / 24 пункта / 9 документов),
дашборд, полный жизненный цикл сделки, права ролей, валидацию и выгрузку.
Скрипт создаёт временную сделку и удаляет её за собой — можно запускать на
рабочем стенде.

На чистой базе часть проверок помечается `SKIP` (нет демо-учётных записей и
поставщиков) — это ожидаемо, а не ошибка.

### Резервная копия базы

```bash
docker compose exec db pg_dump -U ved ved > backup.sql
```

Восстановление:

```bash
docker compose exec -T db psql -U ved ved < backup.sql
```

### Автоматизация на локальном Windows ПК

После локальной настройки создаются две задачи Планировщика Windows для
текущего пользователя:

| Задача | Когда запускается | Что делает |
|---|---|---|
| `VED RTP Local Start` | через 2 минуты после входа в Windows | ждёт Docker Desktop, пересобирает контейнеры, запускает стек и проверяет `/api/health` |
| `VED RTP GitHub Auto Sync` | через 1 минуту после входа в Windows | сохраняет неигнорируемые изменения в Git и отправляет их в `origin/main` |

Логи находятся в игнорируемой Git папке `.runtime`: `.runtime\local-app.log`
и `.runtime\github-sync.log`.

Автосинхронизация не выполняет опасный автоматический merge. Если удалённая
ветка была изменена на другом компьютере одновременно с локальными файлами,
она остановится и запишет причину в лог — файлы не будут перезаписаны.

### Выгрузка в Excel

Кнопка **↓ CSV** на странице «Сделки» — файл с BOM, открывается в Excel
двойным кликом без импорта.

## Разработка

Бэкенд и фронтенд можно поднимать по отдельности.

```bash
# только база
docker compose up -d db

# API на хосте
cd backend
pip install -r requirements.txt
set DATABASE_URL=postgresql+asyncpg://ved:ved_local_pass@localhost:5433/ved
uvicorn app.main:app --reload

# фронтенд на хосте (проксирует /api и /ws на localhost:8000)
cd frontend
npm install
npm run dev        # http://localhost:5173
```

## Расхождение в исходном файле

На листе «Дашборд ВЭД» плитки 7 и 8 подписаны *«Валютный контроль бухгалтерия»*
и *«Подтверждение поступление денег»*, а на листе «Описание блоков» те же номера
описаны как *«Валютный контроль (УНК)»* и *«Order Confirmation»*.

Взят вариант с дашборда как более поздний. Order Confirmation не потерян: это
поле в карточке сделки, тип документа в комплекте и пункт чек-листа 4.2.
